$ARGUMENTS

ハーネス（`my-claude-harness`）を運用ログから直す。月1回か10セッションごとに手で起動する。
**ここがハーネスを変更する唯一の入口。** 作業中のセッションでは書き換えない。

## 1. 読む

doc-storage の全プロジェクトの `claude-doc/worklog/` から「ハーネスへの示唆」欄だけを
横断して読む。ルートは `skill: doc-storage`。対象期間は引数で指定が無ければ前回のレビュー以降。

worklog 以外（plans / reviews）は読まない。示唆欄に書かれていないことは材料にしない。
記憶や印象で補わない。

## 2. 3分類で提案する

| 分類 | 条件 | 提案の中身 |
|---|---|---|
| **昇格** | 同じ文言ルールが2回以上破られた | hook か `permissions.deny` に落とす。具体的な設定・スクリプトの差分まで書く |
| **削除** | 一度も効いた記録が無い / モデル更新で不要になった | 削除する行 |
| **追加** | 同じ事故を繰り返した | 検査 hook か `run-*` skill。文言は最後の手段 |

各提案に、根拠にした worklog のパスと日付を必ず添える。根拠が1件しかないものは
「1件のみ」と明記する。

Claude Code の自動メモリ（`~/.claude/projects/*/memory/`）に同じ指摘が2回以上
溜まっているものも昇格の対象。メモリは個人・一時の置き場、ハーネスは公開リポの昇格先。

## 3. 歯止め

- **削除の提案がゼロのレビューは疑う。** 増える一方なら、効いていないルールを見落としている。
  ゼロのまま出すなら、なぜ削れるものが無いのかを1文で書く
- 文言を足す提案は、hook にも deny にもできない理由を書けるときだけ出す
- 1回のレビューで出す提案は多くて5件。多いなら重大な順に絞る

## 4. 適用

提案を一覧で提示し、**ユーザーが採用を選んだものだけ**適用する。全採用を前提にしない。

適用したら `bash scripts/verify-harness.sh` を通す。落ちたら直す。
**コミットはしない。** 差分を示して人に渡す。

`./install.sh` の再実行が要る変更（ファイルの追加・削除、設定の変更）なら、
その旨を最後に伝える。
