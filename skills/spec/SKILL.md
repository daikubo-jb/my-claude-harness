$ARGUMENTS

**このセッションは上位モデル（`opus` / `fable`）で実行する。**
違うモデルなら、先に `/model opus` を打ってもらってから始める。

作りたいものを詰めて、仕様として書き出す。この会話では実装しない。

`AskUserQuestion` で聞く。技術的な実装方針、UI/UX、エッジケース、懸念、
トレードオフ。当たり前のことは聞かない。本人がまだ考えていない、
判断の分かれる部分を掘る。

十分に埋まったら doc-storage の
`<プロジェクト名>/claude-doc/plans/YYYY-MM-DD-<slug>.md` に書き出す。
配置ルートと書式は `skill: doc-storage`。

仕様に必ず含めるもの:

- 関係するファイルとインターフェースの名前
- スコープ外（今回は作らないもの）
- **完了条件。「そのままコピーして実行できる検証手順」として書く。**
  「テストが通る」では足りない。どのコマンドを打ち、何が出たら通ったのかを書く。
  実装セッションは暗黙の完了条件を推定しない。ここに書いていないものは検証されない

書き出したらパスを示し、次の3つをこの順で打つよう伝える。

```
/model sonnet
/clear
/feature <パス>
```

仕様を詰めた文脈を持ち越さない。実装は安いモデルのセッションで回す。
