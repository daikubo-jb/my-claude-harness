$ARGUMENTS

このセッションは `sonnet` で回す想定。設計から詰め直すなら `skill: spec` へ戻る。

**完了条件を「検証可能な1文」で書けることが前提。** 書けないならここに入らず、
書けるところまで聞くか `skill: spec` へ。

1. **完了条件を確定して提示する。** 検証方法は `.claude/skills/run-*/` か
   プロジェクトの CLAUDE.md から取る。無ければ `/run-skill-generator` で先に記録させる。
   自分から起動したときは、実装に入る前にこの1文を示して合意を取る
2. **探索する。** 読む範囲が広いなら `Explore` に投げる
3. **実装 ⇄ 検証。** 自分で書く。サブエージェントには投げない。
   途中の分岐（`plan-reviewer` / `advisor` / 停止）は共通ルールの表に従う。ここには書かない
4. **完了条件が通ったら `test-runner`。**
   アプリの挙動が変わるなら `/run` で実際に動かして確かめる
5. **指摘 → 修正 → 影響する検証だけ再実行。** 全部は回し直さない
6. **記録する。** 長時間・高リスク・引き継ぎのいずれかなら `doc-writer` に渡す。
   「何を・なぜ・どう変えたか」の要約と、**「ハーネスへの示唆」**を添える

放置して自走させるなら、完了条件を提示してユーザーに `/goal <完了条件>` を打ってもらう。

サブエージェントにはこの会話が見えない。
仕事に必要な文脈はプロンプトに含めて渡す。

作業中にハーネス（`~/.claude`）を書き換えない。
気付いたことは「ハーネスへの示唆」に書くだけにして、変更は `skill: harness-review` で行う。
